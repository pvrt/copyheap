# Техническое задание на разработку: CopyHeap

## 1. Общие требования и архитектура

* **Название приложения:** `CopyHeap`
* **Целевая ОС:** Windows 10 / Windows 11 (x64).
* **Стек технологий (Zero-Dependency & Max Speed):**
* **Язык:** C++20 + нативный **Win32 API** (GDI+ / Direct2D для плавной отрисовки скругленных плашек и векторных иконок).
* **Сборка:** Единый автономный исполняемый файл `CopyHeap.exe` (размер ~1–2 МБ) со статической линковкой runtime-библиотек (`/MT` в MSVC).
* **Требования к системе:** Полное отсутствие внешних зависимостей — пользователю не нужно устанавливать .NET, VC++ Redistributable, WebView2 или любые другие пакеты. Программа работает сразу после скачивания/запуска из любой папки (portable-совместимость).


* **Производительность:**
* Холодный старт: < 30 мс.
* Потребление ОЗУ в фоне: < 8 МБ.
* Нагрузка на CPU в простое: 0% (событийная модель через сообщения ОС без поллинга).


* **Права доступа (Без прав администратора):**
* В манифесте приложения строго указать `level="asInvoker" uiAccess="false"`.
* Приложение никогда не запрашивает UAC и не обращается к защищенным системным директориям (`Program Files`) или веткам реестра `HKEY_LOCAL_MACHINE`.
* Все данные хранятся исключительно в пользовательской директории: `%LocalAppData%\CopyHeap\history.json` (создается автоматически при первом запуске).

## 2. Лимиты данных и правила сортировки

### Модель элемента (`ClipboardItem`)

* `id`: уникальный идентификатор (UUID / timestamp + counter).
* `title`: пользовательское название (строка, может быть пустой).
* `content`: полный текст сниппета (UTF-8).
* `content_hash`: быстрый хеш текста (например, FNV-1a 64-bit или SHA-256) для мгновенной дедупликации.
* `is_pinned`: флаг закрепления (`bool`).
* `created_at`: время создания / последнего копирования (Unix timestamp ms).
* `pinned_at`: время закрепления (Unix timestamp ms, для закрепленных элементов).

### Жесткие лимиты и вытеснение

1. **История незакрепленных записей — максимум 200 элементов:**
* При попадании в буфер 201-го незакрепленного элемента самая старая незакрепленная запись (с минимальным `created_at`) автоматически удаляется.


2. **Закрепленные записи — максимум 20 элементов:**
* Если уже закреплено 20 записей, попытка закрепить 21-ю блокируется с показом аккуратного встроенного уведомления внутри окна: *«Достигнут лимит закрепленных записей (макс. 20)»*.


3. **Дедупликация при копировании из буфера обмена:**
* Если скопированный текст совпадает по хешу с уже существующим **незакрепленным** элементом — старый дубликат удаляется, а запись поднимается на самую верхнюю позицию с обновленным `created_at` (пользовательское `title`, если было задано, сохраняется).
* Если скопированный текст совпадает с уже **закрепленным** элементом — дубликат в историю незакрепленных не добавляется.



### Правила отображения и сортировки

* **Отображаемый заголовок строки:** Если `title` не пуст — выводится `title`. Иначе — первая непустая строка из `content` (с заменой переносов строк и табуляций на пробелы), обрезанная по ширине контейнера с многоточием (`...`).


* **Главное окно (всего до 220 записей: 200 обычных + 20 закрепленных):**
1. Сверху: **незакрепленные** записи (сортировка: `created_at DESC` — свежие сверху).


2. Снизу: **закрепленные** записи (сортировка: `pinned_at DESC` — новые закрепленные выше, старые ниже: *«ниже — старее»*).




* **Нативное контекстное меню в трее (всего до 30 записей):**
1. Верхний блок: до **10 последних незакрепленных** записей (`created_at DESC`).


2. Разделитель (`MF_SEPARATOR`).


3. Нижний блок: до **20 закрепленных** записей (`pinned_at DESC` — старые закрепленные в самом низу).


4. Разделитель (`MF_SEPARATOR`).


5. Системные пункты: **«Открыть»** и **«Выход»**.

## 3. Интерфейс и UX (по макету)

Приложение запускается в фоновом режиме в системном трее (без кнопки на панели задач, стиль окна `WS_EX_TOOLWINDOW` / скрытие при закрытии). Нажатие на системный крестик окна или `Esc` на главном экране скрывает окно (`ShowWindow(SW_HIDE)`), не завершая процесс.

### Экран 1: Главное окно (Список и поиск)

* **Стиль:** Чистый светлый интерфейс в духе Windows 11 (`#F5F5F5` фон окна, скругленные углы окна через `DwmSetWindowAttribute` с `DWMWA_WINDOW_CORNER_PREFERENCE = DWMWCP_ROUND`). Размер окна ~`440 × 540 px` (с поддержкой DPI-масштабирования Per-Monitor V2).
* **Верхняя панель:**
* Поле **«Поиск...»** (белый фон, тонкая рамка `#D0D0D0`, скругление `6px`). Мгновенная фильтрация в реальном времени по вхождению подстроки в `title` или `content` (регистронезависимо, с поддержкой кириллицы и латиницы).


* Кнопка **«Добавить»** справа от поиска (акцентный синий `#0067C0`, при наведении `#005A9E`, белый текст, скругление `6px`) — переключает интерфейс на Экран 2 в режим создания новой записи.




* **Список элементов (кастомный виртуализированный скролл-список):**
* Каждая запись — плашка (`#EAEAEA`, при наведении `#E1E1E1`, скругление `6px`, отступ между плашками `6px`).


* **Клик по плашке:** копирует полный `content` в буфер обмена и показывает краткую визуальную индикацию («Скопировано» / легкая подсветка плашки на 300 мс).
* **Кнопки действий справа внутри каждой плашки (3 иконки):**
1. **Закрепить / Открепить:** контурная иконка канцелярской кнопки для обычных записей; перечеркнутая/активная кнопка для закрепленных.


2. **Редактировать:** иконка карандаша — открывает Экран 2 для редактирования этой записи.


3. **Удалить:** иконка корзины — мгновенно удаляет запись (без модальных окон подтверждения для максимальной скорости работы).







### Экран 2: Создание / Редактирование записи

Открывается внутри того же окна вместо списка:

* **Верхнее поле:** однострочный инпут с плейсхолдером **«Название»** (необязательное поле; позволяет задать короткое имя длинному промпту или сниппету).


* **Основное поле:** многострочный текстовый редактор с вертикальной прокруткой (`Edit` / `RichEdit` без форматирования) для полного текста сниппета.


* **Нижняя панель кнопок (2 кнопки одинаковой ширины):**
* Слева: **«Назад»** (светло-серая кнопка `#EAEAEA`, темный текст) — отменяет изменения и возвращает на Экран 1.


* Справа: **«Сохранить»** (синяя кнопка `#0067C0`, белый текст) — сохраняет изменения (или добавляет новую запись в верх списка, соблюдая лимит 200), сохраняет данные на диск и возвращает на Экран 1.





### Системный трей и контекстное меню

* Иконка `CopyHeap` в области уведомлений (`Shell_NotifyIconW`) с всплывающей подсказкой `CopyHeap`.


* **По левому клику (`WM_LBUTTONUP`) и правому клику (`WM_RBUTTONUP`)** открывается нативное контекстное меню Windows (`CreatePopupMenu` + `TrackPopupMenu` с обязательным `SetForegroundWindow` перед вызовом, чтобы меню корректно закрывалось при клике мимо).


* Клик по любому элементу в меню помещает его полный `content` в буфер обмена.
* **«Открыть»** — показывает и выводит главное окно на передний план.


* **«Выход»** — сохраняет актуальное состояние на диск, удаляет иконку из трея и корректно завершает процесс.

## 4. Технические гарантии надежности и скорости

1. **Мониторинг буфера без задержек и петель:**
* Использовать Win32 API `AddClipboardFormatListener(hwnd)` и обработку `WM_CLIPBOARDUPDATE`.
* **Защита от самокопирования:** При записи текста в буфер самим приложением `CopyHeap` (по клику в списке или меню трея) взводится флаг/сохраняется хеш отправленного текста, чтобы пришедший следом `WM_CLIPBOARDUPDATE` был проигнорирован и не менял порядок элементов.
* **Retry-механизм при обращении к буферу:** Так как `OpenClipboard` может временно возвращать ошибку при одновременном доступе других программ, реализовать до 5 попыток открытия с интервалом 10 мс.
* **Фильтрация мусора:** Обрабатывать только текстовый формат (`CF_UNICODETEXT`), игнорировать пустые строки и строки, состоящие только из пробелов/переносов.


2. **Асинхронное атомарное сохранение на диск:**
* Все операции чтения/поиска выполняются мгновенно в оперативной памяти (`std::vector` / `std::deque`).
* Запись в `%LocalAppData%\CopyHeap\history.json` происходит в фоновом потоке с дебаунсом (через 250 мс после последнего изменения) через запись во временный файл `history.json.tmp` и атомарную замену `MoveFileExW(..., MOVEFILE_REPLACE_EXISTING)` — это исключает повреждение истории при внезапном выключении ПК.


3. **Один экземпляр приложения (Single Instance):**
* При запуске создается именованный мьютекс `Local\CopyHeap_SingleInstance_Mutex`. Если экземпляр уже запущен, новый процесс отправляет ему пользовательское сообщение (`RegisterWindowMessageW(L"CopyHeap_ShowWindow")`), чтобы показать главное окно, и сразу завершается.


4. **Горячие клавиши внутри окна:**
* `Ctrl + F` — перевод фокуса в строку поиска.
* `Esc` — очистка поиска (если введен текст) -> возврат на Экран 1 (если открыто редактирование) -> скрытие окна в трей (если на главном экране).
* `Ctrl + Enter` на экране редактирования — быстрое сохранение записи.
